Hand an agent a task. Review the pull request in a minute.

mexxi is a workflow around the coding agent you already use. Every task gets a fresh worktree, a green verify before and after, rendered QA and an independent review. You get a pull request that shows its proof, and you decide whether to merge.

What /wettaq does with a request

  1. 1

    Fresh worktree

    ibni prepare makes a locked worktree and branch, and sweeps ones whose pull requests have merged.

  2. 2

    Agree what done means

    The agent reads the repository and writes the contract. It asks only about product decisions.

  3. 3

    Green before work

    The repository's verify command must pass first. If it does not, the run stops and reports.

  4. 4

    Implement

    The change lands with tests at the cheapest level that proves it.

  5. 5

    Verify and look

    A full verify, then rendered QA at three viewports, including motion and keyboard use.

  6. 6

    Independent review

    A read-only reviewer judges substantial changes and calls how risky the merge is.

  7. 7

    Pull request

    The branch is pushed without force, with screenshots, GIFs and the evidence.

  8. 8

    You review

    Product decisions and the merge stay with you.

  9. 9

    Follow-ups

    ibni adopt reopens the worktree of an open pull request in a new session.

Three hosts, one set of files

  • OpenCode

    Reads the shared commands, skills and agents. Its config is rendered from yours.

  • Claude Code

    Adds mods: a run pane showing where the run stands, its progress and Jev's triage, and a fixer for risky commands.

  • Codex CLI

    Runs commands as $mexxi-… skills, with a read-only reviewer sandbox.

What’s in the box

  • Commands

    /wettaq delivers a request, /ittestja tests a UI, /lesti prepares a repository, and three more look after the workflow.

  • Agents

    An independent code reviewer and a UI designer, each with the tools it needs and no more.

  • Skills

    Rendered QA, repository mapping, commit and pull request writing, and the review gate.

  • The ibni CLI

    Worktree lifecycle from prepare to publish, with step timings.

  • Guardrails

    Rules forbid force pushes and merges, and a guard backs them up. A loop breaker stops a third identical failure.

  • Retrospectives

    /irrifletti measures how recent sessions went, privately, on your machine.

Install by hand

Terminal 
git clone https://github.com/alexportelli12/mexxi.git ~/workspace/mexxi
cd ~/workspace/mexxi
npm ci
node scripts/install.mjs
node scripts/install.mjs --check   # fails on any drift

Settings live in one file, ~/.config/mexxi/config.json. The first install writes a minimal one; every key has a default.

Your application repository needs one verify command, npm run verify by default. The /lesti prompt above adds one if it is missing.
