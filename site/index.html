Approve your agent’s pull requests without reading every line.

mexxi is a workflow for the coding agent you already use. Each task comes back as one pull request that is tested, checked in a real browser and reviewed by a second agent. Its first screen says whether it is safe to merge and what is left for you to decide.

What you need: Node.js 22.13 or newer, Git, the forge’s CLI (gh for GitHub, glab for GitLab) and one of Claude Code, Codex or OpenCode. Optional: the review tool (OpenCodeReview, ocr), Playwright MCP for browser checks, and ffmpeg for GIFs.

What goes wrong when you hand an agent a task

  • It skips tests

    One run is careful; the next ships without proof.

  • It never looks at the UI

    The code compiles, and nobody has opened the page.

  • It fights its environment

    It retries the same failing command and loses time to shell quoting.

  • You must reverse-engineer its pull request

    You read the whole diff to learn what it did and why.

What /wettaq (build it) does with a request

  1. 1

    Its own copy

    The agent works in a fresh Git worktree on a new branch, so your checkout and other tasks stay untouched.

  2. 2

    Agree what done means

    It reads the repository and writes down what done means. It asks you only about product decisions.

  3. 3

    Start from green

    Your repository’s own checks, npm run verify by default, must pass first. If they fail, it stops and tells you.

  4. 4

    Build it

    It makes the change, with tests at the cheapest level that proves it.

  5. 5

    Check and look

    The checks run again. For UI changes it opens the app in a real browser at phone, tablet and desktop sizes.

  6. 6

    A second opinion

    A reviewer agent that cannot edit code judges larger changes and says how risky the merge is.

  7. 7

    Pull request

    It pushes the branch, never by force, and opens a pull request with screenshots and what was tested.

  8. 8

    You review

    You read the first screen, make the product calls and merge. What to check.

  9. 9

    Follow-ups

    Ask for changes with /wettaq on the same pull request. It picks up the same worktree.

Same request, two pull requests

One request, “show the last sync time on the settings page”, given to the same agent twice in a small demo app. Here is what each pull request tells you about the questions a reviewer asks.

Without mexxi With mexxi
What changed for the user?
The Cloud sync card shows when notes last synced, and a failed sync says so. The same, worded as “Last synced 5 minutes ago” or “Not synced yet”.
Does it work?
npm run verify passes; no new tests. Verify passes with 4 new tests, checked in a browser at 3 sizes, reviewed twice.
What does it look like?
Described in words; no screenshots. Before and after shots, plus the never-synced and failed states.
Is it safe to merge?
No call made; it notes there are no API or store changes. Safe to merge and easy to undo: a page-only change.
What’s left for me?
Not stated. Press Sync now on Settings and check it reads “Last synced just now”.

Three agents, one set of files

  • OpenCode

    Reads the shared commands, skills and agents. Its config is rendered from yours.

  • Claude Code

    Adds a pane beside the chat that shows where the run stands, and quotes risky shell commands before they run.

  • Codex CLI

    Runs commands as $mexxi-… skills, with a reviewer that can only read.

What’s in the box

  • Commands

    /wettaq (build it), /ittestja (test the UI) and /lesti (get a repo ready). Three more look after the workflow: /fassal (write UX principles), /sewwi (change the workflow) and /irrifletti (look back at sessions).

  • Agents

    An independent code reviewer and a UI designer, each with the tools it needs and no more.

  • Skills

    Browser checks, repository mapping, commit and pull request writing, and the review gate.

  • The worktree CLI

    ibni (the worktree CLI) takes each task’s worktree from prepare to publish, with step timings.

  • Guardrails

    Rules forbid force pushes and merges, and a guard backs them up. When one command fails a third time, the agent must stop and rethink.

  • Retrospectives

    /irrifletti measures how recent sessions went, privately, on your machine.

Install by hand

Terminal 
git clone https://github.com/alexportelli12/mexxi.git ~/workspace/mexxi
cd ~/workspace/mexxi
npm ci
node scripts/install.mjs
node scripts/install.mjs --check   # fails on any drift

Settings live in one file, ~/.config/mexxi/config.json. The first install writes a minimal one; every key has a default.

Your application repository needs one verify command, npm run verify by default. The /lesti prompt above adds one if it is missing.
